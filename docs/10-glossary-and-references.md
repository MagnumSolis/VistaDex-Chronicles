# Glossary & References

## Glossary

| Term | Plain-language definition |
|---|---|
| **Mode collapse** | An AI model's tendency to generate similar, common outputs rather than genuinely varied or novel ones. |
| **Sycophancy (in AI)** | A measured tendency for AI models to be overly agreeable or affirming, especially about something the user is proposing themselves. |
| **Entity resolution** | Determining that two differently-worded records actually refer to the same real-world company. |
| **Claim decomposition** | Splitting a longer statement into individual, separately checkable factual claims. |
| **Confidence scoring** | Rating how sure a system is about a conclusion, ideally based on real evidence like source agreement rather than a model's own self-assessment. |
| **Graveyard database** | A structured, searchable record of startups that failed, pivoted, or shut down, along with why. |
| **Objector** | An adversarial agent pass whose sole job is to argue against the system's own conclusion before it's shown as final. |
| **Big-tech clone test** | A structured check for whether a large, resourced company could easily replicate an idea's core value using capabilities it already has. |
| **Verification substitution (H2)** | The hypothesis, from the discarded first VistaDex concept, that more granular AI-generated evidence makes users *feel* more confident while actually *verifying less*. See the [archive](../archive/discarded-concept-claim-verification/README.md). |
